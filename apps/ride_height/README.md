# Ride Height Studio

The owner's 740d xDrive on OEM 21-inch wheels is already about 20 mm below factory height through its existing calibration. The owner's intended feature is temporary physical height control at the measured baseline, about +20 mm (factory), and about +40 mm (20 mm above factory), returning to the lowered baseline after restart. This version does **not** implement arbitrary millimetre targets.

Version 0.5.1 provides full-screen measured-height previews and the two VDP preset commands demonstrated on the car: Standard (`2E DC11 00 08`) and High (`2E DC11 00 10`). VDP responded positively to both. High physically raised the car, and a Standard command returned it to its usual lowered height. High also reverted to Standard during the test, so the app must display the current VDP level and never promise that High stays selected. It does not expose Low: the owner does not want to lower the car further.

The app requires fresh head-unit speed and gearbox signals showing a stationary car in Park. It independently reads VDP's filtered speed (`DD3A`) immediately before each write, reads VDP identity (`F150`), sends only `DC11` with the Standard or High value, and checks `D8EC` for the requested level. It continues to read four relative height sensors (`DC05`); these are not rim-to-fender measurements. The physical measurements entered by the owner stay saved in `ride-height-plan.json`; the selected preview resets to zero on app restart.

The former 0.5.0 build exposed one-second corner fill/vent commands (`DB77`). On this car, VDP rejected the request with UDS NRC `0x22` (conditions not correct), including with the engine running and in an extended diagnostic session. Version 0.5.1 removes the refused corner buttons and contains no `DB77` or `DC2C` write path.

**Calibration incident on 2026-11-03:** A direct ENET diagnostic probe sent `2E DC2C` in the VDP extended session. The VDP accepted the write and changed the front-left S1 calibration offset from its saved original `-21.081808 mm` to `-12.746038 mm`. Sending the original value back to `DC2C` was also accepted but did **not** restore S1. The other three S1 offsets remained unchanged. The original full `DC0B` response and raw bytes are backed up in `outputs/BMW/vdp-probes/vdp-offset-FL-20261103T162504656671Z.json`. No nonvolatile calibration-save routine (`4006`) was called, but persistence across VDP sleep has not yet been checked. The car was found to be on nonlevel ground; perform no further calibration writes until it is on level ground. The `Probe-VDP-Offset.py --execute` path is disabled. Do not describe the car as restored based solely on a positive UDS reply; verify `DC0B` readback. If the original value does not return after VDP sleep, use BMW ISTA's VDP ride-height adjustment procedure on level ground to restore the calibration.

The BMW diagnostic file `C:\EC-APPS\EDIABAS\ECU\VDP_G11.PRG` exposes no verified temporary arbitrary-millimetre setpoint. The separate head-unit LevelControl interface also lists discrete levels, not millimetre values. The desired +40 mm target and individual strut control remain unsolved. A future implementation must identify a manufacturer-supported temporary target or the exact ISTA service procedure and its release/restore semantics before enabling those controls.

Local checks: `python kit/tools/check_signals.py`, `python kit/tools/build.py ride_height`, and `node kit/tools/test_ride_height.js`. These verify catalog compatibility, package generation, fail-closed Park/speed gating, and that the only possible VDP writes are the two preset `DC11` values.
